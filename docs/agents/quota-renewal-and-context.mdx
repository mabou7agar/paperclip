---
title: Quota renewal and task context
---

Company phase-routing defaults and agent overrides accept `unknownResetCooldownSeconds: 0`. This holds an exhausted account when the provider supplies no renewal time. Confirm quota restoration through Usage Health to make the account eligible again. Existing policies retain their configured cooldown; new zero values do not change fallback order, credentials or review independence.

A provider-reported renewal remains eligible for the bounded renewal queue. A control-plane backoff is recorded as `providerQuotaResetSource: backoff`, separately from a provider date. Re-reading a backoff must never upgrade it into a provider-reported reset. Operators can repair older derived metadata from its first trusted recovery-monitor audit event; raw provider failures, usage receipts and account attribution remain unchanged.

Keep one pending renewal continuation per task, preserving its issue, context and original review stage. When correcting a guessed deadline, cancel the unstarted continuation through the scheduler. The cancelled row and its predecessor claim remain terminal. An explicit owner message can authorize one new continuation after inspection; never restore the cancelled row or reset its automatic retry budget. Never treat a seven-day quota message without a date as a one-hour provider reset.

Required reviews can use execution-policy stages on the same issue: review participant, then approval participant. A normal completion transition enters the next stage; a changes-requested decision returns to the recorded owner. Keep the implementation delegation-cycle guard enabled and reuse existing reviews.

Task-context redaction and account quota reads use indexes on the legacy embedded issue identity and the immutable connection attribution. Migration 0337 includes both definitions. On a busy installation, prebuild those same definitions with `CREATE INDEX CONCURRENTLY IF NOT EXISTS` outside a transaction and verify `pg_index.indisvalid` and `indisready`; the transactional migration then adopts them. Online index creation requires no application restart. Redaction, authorization and response contracts are unchanged.

Cancelling a quota wait before its eligibility time is not a failed provider process. Recovery verifies its original predecessor, future deadline, cancellation fence, unclaimed runtime and lack of conflicting execution/cleanup evidence before classifying it as never dispatched. Existing saved owner input can then pass the normal continuation gate exactly once. A cancellation after eligibility, unknown predecessor, launch/provider event, process identity or unfinished cleanup retains the hold. This proof grants no permission to replay earlier provider actions.

A quota gate reached by an explicit owner message can schedule its one verified renewal continuation. The successor receives a new durable authorization tied to the unchanged original comment. The scheduler verifies the control-plane no-dispatch receipt, absence of launch/provider/cleanup evidence, current task ownership and the original comment hash. Concurrent requests coalesce to one scheduled run; a second quota renewal in that chain exhausts the existing budget. An edited/deleted comment, unknown reset, unrelated cancellation or conflicting execution evidence cannot inherit this permission.

Managed Codex also repairs its retained rollout index when ACP discovers the exact persisted session key while the outer Paperclip session row is absent. The key remains scoped to company, agent, task, account and configuration. Only the existing immutable rollout path is relocated from the discarded login home; its session ID and transcript are preserved. Another task/account cannot borrow that repair. A persistent-session repair error remains terminal for automatic retries, including during the initial handshake.

When a child finishes during a dependency-blocked interaction, a running triage prompt cannot be upgraded after dispatch. If admission confirms all blockers are now ready, the concrete child-completion event is retained as one deferred continuation. Normal completion releases it to a new turn on the same task and native session. Repeated events with the same idempotency key share the saved continuation. A partial completion with unresolved blockers stays in triage; queued prompts can still absorb new input before dispatch. This changes neither review approvals nor provider retry budgets.

A worker's self-handoff waits for its owned adapter and cleanup before assignment commits. Stop acknowledgement can precede lease and scratch cleanup. If the initial 60-second wait expires, the control plane grants one additional 60-second cleanup window only when the cancelled source carries the exact handoff marker and a durable adapter Stop acknowledgement. It does not resend Stop, restart a provider, change native sessions, or reset retry budgets. Unacknowledged cancellation and cleanup that remains unfinished retain the hold; unrelated requests cannot inherit this grace period.

Company model defaults can enable `apiQuotaRecheckSeconds: 1800` for exhausted Anthropic-compatible Messages API connections. Omitted or zero preserves the existing manual hold. `apiQuotaRecheckOverrides` maps connection IDs to another interval or zero; checks are shared across agents, not repeated for each fallback chain. Intervals range from 300 to 86400 seconds. The first automatic check waits at least one interval after the failed request. Subsequent failures back off exponentially, respect Retry-After and stop at a one-day interval. Subscription renewal dates and the configured fallback priority remain unchanged.

Standard Anthropic API connections use the official Messages endpoint and API-key header. A custom Messages connection retains its configured endpoint and authentication; other protocols are never redirected to Anthropic. Migration 0339 adds a partial index of quota failures so historical successful runs and their large context snapshots do not slow account eligibility checks. Prebuild this exact index concurrently on busy installations before the transactional migration.

Each check sends only “Reply OK.” with an eight-token output cap to the connection’s existing approved endpoint. It never loads task planning context, requests prompt caching, follows redirects, substitutes ambient credentials or starts an agent. Durable connection-scoped claims survive restarts; an uncertain response retains the hold until the next due check. Rotation, revocation or changed sharing invalidates stale probe results. Numeric probe usage appears in Usage Health, with missing usage left unknown; monetary charges remain provider-priced, not assumed to be zero.

A successful request clears only its exact prior failure receipt. Recovery promotes an already scheduled, still eligible quota continuation in place, preserving its run identity, native context and retry count. It does not restart terminal work, invent a renewal date or bypass review/approval policy. Recovery renews its delivery claim during long batches and fences an owner whose claim has been replaced. Repeated or concurrent recovery sweeps cannot create a second continuation.
